Support

Choose the route that matches the problem and keep private information out of public reports.

Never publish: phone numbers, login codes, Telegram API credentials, session files, personal media, metadata snapshots, databases, Recovery Keys, signing material, or unredacted private logs.

Application bugs

Search existing reports, then submit a sanitized issue with the TeleVault version, Android version, device model, installation source, reproducible steps, expected behavior, actual behavior, and safe screenshots or logs.

Report a bug

Feature requests

Describe the user problem and expected outcome. Changes involving permissions, encryption, login, sync, restore, storage formats, or dependencies require maintainer review.

Propose a feature

Privacy and deletion

Use the public inquiry route only for non-sensitive questions about the Privacy Policy or deletion process. Do not include account identifiers, evidence containing personal data, private media, or credentials.

Submit an inquiryDeletion guidance

Security vulnerabilities

Report vulnerabilities privately. Do not open a public issue containing exploit details, credentials, personal data, or proof-of-concept material.

Report privately

Build and contribution questions

Use the repository documentation and GitHub Issues for reproducible source-build problems. Include tool versions and sanitized output, never local credentials or signing files.
