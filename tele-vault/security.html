Security

Report vulnerabilities privately and give maintainers time to investigate before public disclosure.

On this pageReport privatelySupported versionsSensitive areasLimitations

1. Report a vulnerability

Use GitHub Private Vulnerability Reporting as the primary reporting path. Include affected versions, impact, reproducible steps, and a minimal proof of concept without real user data.

Do not use public issues for exploit details, credentials, Telegram session material, personal media, database files, metadata backups, unredacted logs, or active attack information.

If private reporting is unavailable, open only a minimal public issue stating that a private security contact is needed. Do not include sensitive details.

2. Supported versions

Security fixes target the latest source on the default branch and the latest published Android build, when one exists. Older builds, unofficial binaries, modified forks, and experimental platforms may not receive fixes.

Response and remediation times are targets rather than guarantees. See the repository security policy for the current support table and reporting expectations.

3. Security-sensitive areas

  • Telegram authentication, TDLib sessions, API credentials, and channel access.
  • Vault encryption, key derivation, credential reset, biometrics, and decrypted temporary files.
  • App lock, retry limits, lockout state, and device-authentication boundaries.
  • Media permissions, file selection, sharing, deletion, restore, and local paths.
  • Metadata package encryption, import conflict handling, safe uninstall, and Telegram metadata channels.
  • Drift/SQLite metadata, secure storage, logs, notifications, build signing, and native libraries.
  • Background services, upload confirmation, bucket routing, and dependency supply chain.

4. Current security limitations

  • Normal non-vault uploads are not currently client-side encrypted by TeleVault before upload.
  • Telegram and TDLib remain third-party trust dependencies.
  • Application metadata is stored locally and local database encryption is not guaranteed by this policy.
  • Rooted, compromised, or unlocked devices can undermine application safeguards.
  • Background execution, permissions, and secure storage vary by Android device and version.
  • Open-source review reduces opacity but does not guarantee the absence of vulnerabilities.

TeleVault makes no guarantee of complete security, uninterrupted service, or successful recovery. Keep independent backups and use strong device and Telegram account security.

5. Recognition and disclosure

Maintainers may coordinate disclosure timing and acknowledge reporters with permission after a fix is available. Do not access data beyond what is necessary, disrupt users, demand payment, or publicly disclose an unresolved vulnerability without coordination.
