Security

Report vulnerabilities privately and give maintainers time to investigate before public disclosure.

1. Report a vulnerability

Use GitHub Private Vulnerability Reporting. Include affected versions, impact, reproducible steps, and a minimal proof of concept without real user data.

Do not use public issues for exploit details, credentials, Telegram session material, personal media, databases, metadata snapshots, Recovery Keys, unredacted logs, or active attack information.

2. Supported versions

Security fixes target the latest source on the default branch and the latest official Android build, when one exists. Older builds, unofficial binaries, modified forks, and experimental platforms may not receive fixes.

See the repository security policy for the current support table and disclosure expectations.

3. Current protections

  • Vault v3 uses chunked authenticated encryption, independent per-file data keys, unique object identifiers, and a separate high-entropy Recovery Key.
  • Metadata v5 snapshots use authenticated encryption, exclude recovery secrets, and are verified before database replacement.
  • TDLib sessions, Drift databases, cache, temporary files, secure storage, and review-mode data use application-private or isolated namespaces.
  • Uploads remain sequential, use durable Telegram flood-wait handling, confirm final message success, and reconcile uncertain operations after restart.
  • WorkManager and the foreground data-sync service coordinate through one queue owner and one TDLib storage owner per runtime namespace.
  • Release validation checks API 36, 16 KB native-page support, reviewed native hashes, manifest permissions, signing state, secrets, and prohibited artifacts.

4. Security limitations

  • Normal non-vault uploads are not client-side end-to-end encrypted by TeleVault before upload.
  • Telegram and TDLib remain third-party trust dependencies and Telegram processes uploaded content.
  • A lost Vault Recovery Key may make encrypted Vault content permanently unrecoverable.
  • Rooted, compromised, unlocked, or poorly secured devices can undermine application safeguards.
  • Android, device vendors, network conditions, low storage, and foreground-service limits can interrupt backup work.
  • Open-source review and automated validation reduce risk but do not guarantee the absence of vulnerabilities.

Keep Android updated, enable Telegram two-step verification, use strong device security, protect the Recovery Key offline, verify important uploads, and retain an independent backup.

5. Recognition and disclosure

Maintainers may coordinate disclosure timing and acknowledge reporters with permission after a fix is available. Do not access data beyond what is necessary, disrupt users, demand payment, or publicly disclose an unresolved vulnerability without coordination.
