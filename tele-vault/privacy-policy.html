1. Scope and definitions

This policy explains how the TeleVault Android application accesses, stores, and transmits information. It applies to the distributed application and its current open-source implementation. It does not replace Telegram's privacy policy or terms.

"Local" means data stored on the device where TeleVault is installed. "Telegram" means the third-party Telegram service accessed through TDLib. "Bucket" means a Telegram channel selected or created for TeleVault backup.

2. Data the application accesses

Photos, videos, and media metadata

With Android permission, TeleVault scans photos and videos available through the device media library. It may access media bytes and metadata needed for display, organization, deduplication, queueing, and backup, including asset identifiers, file names, paths exposed by Android, media type, size, dimensions, timestamps, album relationships, hashes, labels, and sync state.

Telegram authentication and account information

TeleVault uses TDLib to authenticate an existing Telegram account. Depending on the authentication state, Telegram may require a phone number, login code, two-step verification password, or other account security step. TeleVault also receives Telegram account profile information and channel information required to display the signed-in account and manage buckets.

Authentication requests and Telegram data are processed by TDLib and Telegram. Users must never send login codes, passwords, API credentials, or Telegram session files to Shagiz Technologies through a public issue.

Local diagnostics

The reviewed implementation includes local diagnostics and operational records used to troubleshoot app behavior. No external analytics or telemetry SDK was identified during the open-source preparation audit. Diagnostics must not intentionally include private media content, authentication credentials, or secrets. Users should review and redact logs before sharing them.

3. Data stored locally

TeleVault uses a local Drift/SQLite database and device storage for application state. Local data may include bucket records, media metadata, labels, upload status, Telegram message references, retry information, settings, vault flags, metadata-backup state, and local diagnostic entries. TDLib separately stores Telegram session and database files in the application's private storage.

Credentials and derived security values intended for protected storage use platform storage mechanisms where implemented. Device compromise, unlocked devices, insecure backups, and operating-system vulnerabilities can still expose local data.

4. Data transmitted to Telegram

When a backup runs, selected media and related upload information are sent through TDLib to Telegram channels associated with the authenticated account. TeleVault may also upload encrypted metadata backup packages to a dedicated or selected Telegram channel when that feature is enabled or invoked.

Telegram and TDLib process authentication, channel access, message creation, file transfer, storage, and retrieval. Telegram has its own privacy practices, infrastructure, account controls, terms, limits, and retention behavior. A channel being private does not mean Telegram is technically unable to process its content, and TeleVault does not control Telegram's infrastructure.

TeleVault does not operate a separate media-storage backend in the current implementation. Shagiz Technologies does not have application-server access to user bucket channels. This does not eliminate processing by Telegram, operating systems, app distribution platforms, network providers, or user-selected sharing destinations.

5. Vault and encryption boundaries

Normal backup limitation: Normal non-vault photos and videos are not currently client-side encrypted by TeleVault before upload to Telegram.

Media intentionally moved through TeleVault's vault flow is encrypted by TeleVault before its vault upload path. Vault encryption protects that flow, not every media upload. Vault security depends on the user's TeleVault credential or supported device authentication, key handling, device security, and correct use of the feature.

TeleVault does not claim end-to-end encryption for ordinary backups. Telegram's treatment of uploaded files is governed by Telegram's implementation and policies.

6. Metadata backup behavior

TeleVault can create encrypted metadata backup packages for recovery and safe-uninstall workflows. Depending on configuration, packages may be shared by the user or uploaded to Telegram. A metadata package can contain application metadata needed to reconstruct buckets and file states; it is not necessarily a copy of every media file.

Users are responsible for protecting passphrases and deleting old packages from Telegram, email, file storage, or any other destination they selected. Losing a passphrase may make an encrypted package unrecoverable.

7. Android permissions and purposes

  • Photos and videos / media library: scan, display, organize, select, and back up supported media.
  • Internet: communicate with Telegram through TDLib and open user-selected web resources.
  • Notifications: show backup progress and foreground synchronization status where Android requires or permits it.
  • Foreground data sync: continue eligible auto-backup work while TeleVault is not visible.
  • Biometric or device authentication: use supported device security for app or vault access when the user enables it.
  • Legacy external storage access on older Android versions: read supported media where modern scoped media permissions are unavailable.

Permission availability and behavior vary by Android version, device vendor, and user choice. Denying a permission may disable the related feature.

8. Third-party libraries and services

TeleVault uses Flutter and open-source packages for application functions, including TDLib/libtdjson for Telegram access, Drift/SQLite for local metadata, media-library plugins, secure storage, local authentication, connectivity, notifications, file selection, and sharing. Package licenses are available in the application and source repository.

Telegram is the primary third-party network service in the backup flow. Links opened from TeleVault may be handled by the user's browser and are subject to that browser and destination's policies.

9. Retention and deletion

Local metadata remains until the app deletes it, the user clears application storage, or Android removes it during uninstall. Logging out terminates the local Telegram session, but users should not assume that logout deletes every local metadata record unless the current app flow explicitly confirms that action.

Uninstalling TeleVault normally removes its local application data. It does not automatically delete Telegram bucket channels, messages, files, or metadata packages stored in Telegram or elsewhere. Users must delete those items from Telegram, supported TeleVault controls, or the destination where they stored a package.

Shagiz Technologies cannot directly delete data held in a user-controlled Telegram account. See Data & Deletion for practical steps.

10. Security safeguards and limitations

TeleVault uses application-private storage, platform secure storage where implemented, encrypted vault and metadata-package flows, and Telegram's authenticated TDLib session. No safeguard can guarantee security. Device compromise, weak credentials, misconfiguration, software defects, dependency vulnerabilities, network attacks, and Telegram account compromise remain possible.

Keep Android updated, use strong device security and Telegram two-step verification, protect metadata passphrases, and retain an independent backup of important files.

11. Children

TeleVault is not designed or marketed specifically for children. Eligibility also depends on Telegram's terms and applicable law. A parent or guardian should supervise use where required.

12. International third-party processing

Telegram and other platform providers may process data in countries different from the user's country. Their processing locations and safeguards are governed by their own policies and applicable law. Shagiz Technologies does not select Telegram's processing locations.

13. Policy changes

This policy may change as TeleVault features, dependencies, permissions, or legal requirements change. The effective and last-updated dates will be revised, and material changes should be communicated through the application, release notes, repository, or this site where practical.
